# Postman API Automation with Newman

This repository contains a Postman Collection v2.1 API test suite for the public ReqRes REST API and the public DataAccess Number Conversion SOAP service. GitHub Actions runs the collection with Newman and publishes an HTML Extra report as a workflow artifact and on GitHub Pages.

## Prerequisites

- [Postman](https://www.postman.com/downloads/) 10 or later, or [Node.js](https://nodejs.org/) 20 or later
- Internet access to `https://reqres.in` and `https://www.dataaccess.com`
- **No authentication is required** for the requests currently in the collection

## Repository files

| File | Purpose |
|---|---|
| `reqres.postman_collection.json` | Postman collection containing REST and SOAP requests and test scripts |
| `Environmentreqres.postman_environment.json` | Postman environment with the ReqRes base URL |
| `.github/workflows/blank.yml` | Runs Newman on pushes to `main` and publishes the HTML report |
| `.github/workflows/pynt.yml` | Optional manual Pynt CLI security-test example |
| `ISSUE_ANALYSIS.md` | Known test, maintenance, and documentation gaps |

## Environment variables

The environment defines:

| Variable | Value | Used for |
|---|---|---|
| `url` | `https://reqres.in` | ReqRes REST request URLs |

The REST URLs use `{{url}}`, so the base URL can be changed by editing the environment.

## Run in Postman

1. Open Postman.
2. Select **Import** and import both:
   - `reqres.postman_collection.json`
   - `Environmentreqres.postman_environment.json`
3. Select the `Environmentreqres` environment from the environment selector.
4. Open the `reqres` collection.
5. Select **Run** to open the Collection Runner.
6. Run the collection and verify the iteration summary.

## Run with Newman locally

Install Node.js 20, then run:

```bash
npm install -g newman newman-reporter-htmlextra
mkdir -p testResults
newman run reqres.postman_collection.json \
  -e Environmentreqres.postman_environment.json \
  -r htmlextra \
  --reporter-htmlextra-export testResults/index.html \
  --reporter-htmlextra-darkTheme
```

Open `testResults/index.html` in a browser. By default, Newman exits with a non-zero status if collection assertions fail.

## Collection overview

| Request | Method | URL | Main checks |
|---|---|---|---|
| List Users | `GET` | `{{url}}/api/users?page=2` | Status 200, JSON content type, response fields, non-empty data, URL format |
| Create User | `POST` | `{{url}}/api/users` | JSON schema, content type, response time below 1000 ms |
| Update User | `PUT` | `{{url}}/api/users/2` | Status 200 and required response fields |
| Patch Update | `PATCH` | `{{url}}/api/users/2` | Non-empty response fields and response time below 1000 ms |
| Delete User | `DELETE` | `{{url}}/api/users/2` | Empty response-body check |
| SOAP NumberToWords | `POST` | `https://www.dataaccess.com/webservicesserver/NumberConversion.wso` | XML content type and SOAP response structure |

### Create User example

Request:

```http
POST https://reqres.in/api/users
Content-Type: application/json

{
  "name": "morpheus",
  "job": "leader"
}
```

The public ReqRes API may echo or return the following shape:

```json
{
  "name": "morpheus",
  "job": "leader",
  "id": "<generated-id>",
  "createdAt": "<timestamp>"
}
```

The exact ID and timestamp are generated by the external service and can vary.

### List Users example

```http
GET https://reqres.in/api/users?page=2
```

The response is a JSON object with pagination fields and a `data` array. The collection visualizes selected user fields in the HTML report.

### SOAP NumberToWords example

The request sends XML to the Number Conversion service. Example payload value: `500`.

```xml
<?xml version="1.0" encoding="utf-8"?>
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
  <soap:Body>
    <NumberToWords xmlns="http://www.dataaccess.com/webservices/">
      <ubiNum>500</ubiNum>
    </NumberToWords>
  </soap:Body>
</soap:Envelope>
```

A successful response is expected to contain a SOAP envelope, a `NumberToWordsResponse`, and a non-empty `NumberToWordsResult`.

## CI execution

The `Test-Build` workflow in `.github/workflows/blank.yml`:

- runs on every push to `main`;
- checks out the repository;
- installs Node.js 20, Newman, and `newman-reporter-htmlextra`;
- executes the collection and environment files;
- exports `testResults/index.html`;
- uploads `testResults/` as the `RunReports` artifact;
- publishes the report directory to GitHub Pages.

To run the workflow manually, open **Actions**, select **Test-Build**, and use **Run workflow**. The workflow currently does not define `workflow_dispatch`, so there is no manual-run button until that trigger is added.

To view a workflow report:

1. Open **Actions**.
2. Select a completed **Test-Build** run.
3. Download **RunReports** from **Artifacts**.
4. Open `index.html` from the downloaded archive.

## Optional Pynt workflow

`.github/workflows/pynt.yml` downloads a separate example collection from Pynt and can be started manually. It requires the `PYNT_CREDENTIALS` environment variable to be populated from the `YOURPYNTID` GitHub Actions secret.

This workflow is independent of the ReqRes collection and does not use `Environmentreqres.postman_environment.json`.

## Troubleshooting

| Symptom | Likely cause | Check |
|---|---|---|
| `Could not get any response` | DNS, network, proxy, or endpoint outage | Verify outbound access to the endpoint and rerun with a stable network |
| TLS or certificate error | Repository/container certificate or proxy issue | Update CA certificates and confirm local proxy settings |
| `{{url}}` unresolved | Environment not selected or not passed to Newman | Select `Environmentreqres` in Postman or use `-e Environmentreqres.postman_environment.json` |
| Newman assertion fails | External API changed, or a test assumption is brittle | Review the HTML report, failing request, response, and `ISSUE_ANALYSIS.md` |
| Response time assertion fails | External network latency exceeded 1000 ms | Verify the threshold in the Create or Patch request; consider an environment-specific limit |
| Delete User test errors | The test currently parses the body as XML even though a 204 response has no content | Follow the known fix in `ISSUE_ANALYSIS.md` section 5 |
| SOAP response parsing fails | `Content-Type`, SOAP namespace, or upstream response changed | Inspect the raw response and confirm the SOAPAction and XML namespace |
| GitHub Pages report is missing | Push workflow did not run or Pages permissions/configuration failed | Review workflow logs, Pages settings, and the `github_token` permissions |

## Maintenance notes

- External endpoints are public demos and may change, enforce rate limits, or become unavailable.
- The collection contains no negative test cases; extend it for 400/404/validation coverage when requirements are known.
- Fixed user ID `2` and static payload values can be replaced by environment variables or data files for repeatable suites.
- Review `ISSUE_ANALYSIS.md` before changing tests: it identifies known assertion and collection-structure issues.
- When adding variables, keep the environment key names stable and document them in this README.
- Add or update tests with request changes and verify both Newman locally and in GitHub Actions.
